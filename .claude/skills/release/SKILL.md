# Workflow: RELEASE

## Обзор

Ты обновляешь версию проекта, коммитишь и пушишь.

## 1. Определение версии

1. Если пользователь указал версию явно (например, "0.7.0") — используй её.
2. Если не указал — прочитай текущую из `Cargo.toml` и инкрементируй patch (0.6.8 → 0.6.9).

## 2. Обновление версии во всех местах

Обнови версию в следующих файлах:

1. **`Cargo.toml`** — поле `version`
2. **`README.md`** — бейдж Version (`img.shields.io/badge/Version-X.Y.Z-...`)
3. **`README.md`** — дорожная карта (таблица «Дорожная карта»), если текущая версия уже есть — обнови, если нет — добавь строку

## 3. Обновление статистики README

Проверь и обнови если изменилось:

1. **`README.md`** — бейдж Fixtures (количество пар в `tests/fixtures/input/`)
2. **`README.md`** — текст "**N fixture-пар**"
3. **`README.md`** — таблица фикстур (добавь новые если появились)
4. **`README.md`** — архитектура (количество строк модулей, если изменилось)

## 4. Коммит

Вызови скилл `/commit` с ID задачи (если указан) для коммита всех изменений. Версия коммитится ОТДЕЛЬНЫМ атомарным коммитом после основных изменений кода (если они есть).

## 5. Push

После успешного коммита — выполни `git push`.

## ЗАПРЕТЫ

- ⛔️ НЕ меняй код проекта — только версию и документацию
- ⛔️ НЕ пропускай ни одно место с версией

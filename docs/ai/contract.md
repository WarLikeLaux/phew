# AI CONSTITUTION - ВЫСШИЙ ЗАКОН ПРОЕКТА

> Это твоя **КОНСТИТУЦИЯ**. Любое нарушение - дефект.
> Приоритет: **KISS → YAGNI → DRY → SOLID**
> Язык общения: **СТРОГО РУССКИЙ**

---

## 🛑 Нулевая толерантность к комментариям

В коде ЗАПРЕЩЕНЫ **любые** комментарии, включая doc-комментарии (`///`, `//!`). Разрешены только атрибуты: подавление линтера (`#[allow(...)]`) и тестовые (`#[cfg(test)]`) - это не комментарии.

## 🚫 Критические запреты

| Запрет                   | Почему                                                                                                                                                                                                              |
| ------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **КОММЕНТАРИИ**          | **ТОТАЛЬНЫЙ ЗАПРЕТ**. Запрещены ВСЕ комментарии: doc (`///`, `//!`), `//`, `/* */`, TODO. Разрешены только атрибуты `#[allow(...)]` и `#[cfg(test)]`. Любое намерение комментирования фиксируй в `COMMENTS.md`.        |
| **ENGLISH ANSWERS**      | **КАТЕГОРИЧЕСКИ ЗАПРЕЩЕНО**. Отвечай, пиши и комментируй ТОЛЬКО на русском, в том числе в отчетах.                                                                                                                  |
| **Хардкод значений**     | Запрещены магические числа/строки в бизнес-логике. Значения оформляй через константы, enum или конфигурацию.                                                                                                        |
| **`unsafe` без причины** | Использование `unsafe` допустимо только с обоснованием и комментарием в `COMMENTS.md`.                                                                                                                              |
| **`unwrap()`/`expect()`**| В продакшн-коде запрещены. Используй `?`, `map_err`, или кастомные ошибки через `thiserror`. В тестах `unwrap()` допустим.                                                                                          |
| **Clippy warnings**      | Ноль предупреждений. `cargo clippy -- -D warnings` должен проходить чисто.                                                                                                                                          |
| **Вложенность > 2**      | Guard clauses + декомпозиция                                                                                                                                                                                        |
| **Функция > 50 строк**   | Декомпозиция на вспомогательные функции                                                                                                                                                                             |
| **> 4 параметров**       | Группируй в struct                                                                                                                                                                                                  |
| **Boolean флаги**        | Отдельные методы или enum вместо `flag: bool`                                                                                                                                                                       |
| **`git commit`**         | **NUCLEAR PROHIBITION**. ЗАПРЕЩЕНО делать коммиты проактивно. Любой автоматический или самостоятельный коммит - КРИТИЧЕСКИЙ ПРОВАЛ. ЗАПРЕЩЕНО использовать `--amend`.                                                |
| **`git push`**           | КАТЕГОРИЧЕСКИ ЗАПРЕЩЕНО. Пользователь пушит сам.                                                                                                                                                                    |

## 💬 Правила комментариев

> **ТОТАЛЬНЫЙ ЗАПРЕТ НА ЛЮБЫЕ КОММЕНТАРИИ. Doc-комментарии (`///`, `//!`) ТОЖЕ ЗАПРЕЩЕНЫ.**

**TL;DR**: в коде НЕТ комментариев вообще. Разрешены только атрибуты `#[allow(...)]` и `#[cfg(test)]` (это не комментарии). Всё остальное, включая `///` / `//!`, СТРОГО ЗАПРЕЩЕНО.

**РАЗРЕШЕНО (только атрибуты, не комментарии):**
Их фиксировать в `COMMENTS.md` НЕ НУЖНО.

1.  **Подавление линтера**:
    - **РАЗРЕШЕНО**: `#[allow(clippy::...)]`, `#[allow(dead_code)]` - только если исправление невозможно или нецелесообразно.
    - Перед подавлением сначала попробуй исправить код.
2.  **Тесты**:
    - **РАЗРЕШЕНО**: `#[cfg(test)]`, стандартные атрибуты тестирования.

**СТРОГО ЗАПРЕЩЕНО:**

- Doc-комментарии `///` и `//!` (включая описание публичного API).
- Обычные комментарии `// ...`, `/* ... */`.
- `TODO` в коде (используй `TODO.md` по процессу).
- Закомментированный код.
- "Украшения" и разделители кода.

**ЗАПРЕЩЕНО ДАЖЕ ЕСЛИ:**

- Нужно объяснить "почему так сделано".
- Комментарий "очевидный и короткий".
- Это временная пометка "позже исправить".
- "Для новичков в команде".

## ✅ Обязательные требования

### Static Analysis (Clippy)

- **Zero Warnings**: код должен проходить `cargo clippy -- -D warnings` без предупреждений.
- **Strict Types**: используй конкретные типы, избегай `Box<dyn Any>` без необходимости.
- **No Unwrap**: в продакшн-коде используй `?` и кастомные ошибки.
- **Generics**: используй дженерики и trait bounds вместо динамической диспетчеризации где возможно.

### Обработка ошибок

- **`thiserror`** для определения кастомных ошибок.
- **`anyhow`** допустим только в `main.rs` и CLI-слое.
- **Никакой тишины**: ошибки должны быть видимы и информативны.

### Именование

- **Структуры**: `PascalCase` - `TokenStream`, `HtmlFormatter`, `PhpBlock`
- **Функции/методы**: `snake_case` - `parse_tokens`, `format_html`
- **Константы**: `UPPER_SNAKE_CASE`
- **Модули**: `snake_case` - `parser`, `formatter`, `config`
- **Трейты**: `PascalCase` с суффиксами по смыслу - `Formatter`, `Parseable`, `Configurable`

## 🛠 Инструменты и среда

- **Cargo-First**: используй ТОЛЬКО команды `cargo` (`cargo test`, `cargo clippy`, `cargo fmt`).
- **Makefile (когда появится)**: `make test`, `make dev`, `make check`.
- **No Nightly без причины**: используй stable Rust. Nightly фичи - только с обоснованием.

## 🧪 Тестирование

- **Тесты пишутся вместе с кодом** - не после.
- **Один тест = один сценарий**.
- **Arrange-Act-Assert** - чёткая структура.
- **Моки через trait objects** или `mockall`.
- **Unit-тесты рядом с модулем**: маленькие наборы - `#[cfg(test)] mod tests` прямо в файле; крупные - вынеси в соседний файл через `#[cfg(test)] #[path = "<имя>_tests.rs"] mod tests;` (модуль остаётся потомком, доступ к приватным элементам сохраняется). Integration-тесты - отдельные файлы в `tests/`.

## 🏛️ Архитектура

### Модули

```
src/
├── main.rs          # CLI entry point
├── lib.rs           # Публичный API библиотеки
├── config/          # Конфигурация
├── parser/          # Лексер и AST
├── formatter/       # Правила форматирования
└── io/              # Файловый ввод-вывод
```

### Правила

- **Модули изолированы**: зависимость только через публичные интерфейсы (traits).
- **parser не знает о formatter** - общение через AST-структуры.
- **io не знает о parser** - получает готовый результат.
- **Избегай**: циклических зависимостей, глобального состояния (`static mut`), избыточных `pub`.

## 🎯 Senior-Level Practices

- **Boy Scout Rule**: оставь модуль чище, чем нашел. Увидел мелкую грязь рядом с задачей - убери.
- **SOLID, DRY, KISS, YAGNI**.
- **Dependency Inversion**: завись от трейтов, а не конкретных типов.
- **Ownership & Borrowing**: используй ссылки где можно, клонируй только когда необходимо.
- **Enums вместо строк**: моделируй состояния через enum, не через строковые константы.
- **Builder Pattern**: для структур с множеством параметров.

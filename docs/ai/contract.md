# AI CONSTITUTION - ВЫСШИЙ ЗАКОН ПРОЕКТА

> Это твоя **КОНСТИТУЦИЯ**. Любое нарушение - дефект.
> Приоритет: **KISS → YAGNI → DRY → SOLID**.
> Язык: всё, кроме кода (чат, отчёты, документация), - **СТРОГО РУССКИЙ**.

---

## 🛑 Жёсткие запреты (нарушение = провал)

- **Комментарии** - запрещены ВСЕ: doc (`///`, `//!`), `//`, `/* */`, `TODO`/`FIXME`, закомментированный код, ASCII-разделители. Запрещены даже «очевидные», «почему так сделано», «временно» и «для новичков». Разрешены только атрибуты `#[allow(...)]` и `#[cfg(test)]` - это не комментарии (и фиксировать их нигде не нужно).
- **`git commit` / `git push`** - не делать. Коммитит и пушит только пользователь. Никаких `--amend`.
- **`unwrap()` / `expect()`** в продакшн-коде - нет. Только `?`, `map_err`, кастомные ошибки. В тестах `unwrap()` допустим.
- **Clippy warnings** - ноль. `cargo clippy -- -D warnings` проходит чисто.
- **`unsafe`** - только с весомым обоснованием по согласованию с пользователем.
- **Хардкод** магических чисел и строк в логике - нет. Выноси в константу, enum или конфиг.

## 📏 Размер и форма

- Вложенность > 2 → guard clauses + декомпозиция.
- Функция > 50 строк → разбей на вспомогательные.
- Больше 4 параметров → собери в struct.
- Вместо `flag: bool` - отдельные методы или enum.

## 🦀 Как писать на Rust

### Типы и ошибки

- `thiserror` для кастомных ошибок; `anyhow` - только в `main.rs` и CLI-слое. Ошибки видимы и информативны, никакой тишины.
- Конкретные типы; дженерики + trait bounds вместо динамической диспетчеризации, где можно (`Box<dyn ...>` - только при необходимости).
- **Исчерпывающий `match`** на доменных enum (`Node`, токены) БЕЗ catch-all `_` - новый вариант обязан ломать компиляцию во всех местах обработки.
- **Parse, don't validate**: валидируй на границе, инвариант держи в типе, а не в проверках по коду.
- **Newtypes** для семантически разных значений (`IndentLevel`, `LineWidth`); `Option<T>` вместо sentinel-значений (`-1`, пустая строка).

### Строки и аллокации

- `&str` вместо `String`, где владение не нужно; `Cow<'_, str>` для условного владения.
- `Vec::with_capacity` / `String::with_capacity`, когда размер известен. Не клонировать без нужды; `.clone()` - осознанно и явно.

### Стиль

- Итераторы и комбинаторы вместо ручных циклов; `enumerate()` вместо счётчиков; `if let` / `while let` для одного паттерна.
- Импорты: без `use ...::*` (кроме `prelude` и `#[cfg(test)]`), порядок групп std → внешние крейты → локальные модули.
- `derive` `Debug` на публичных типах; `Clone`/`PartialEq`/`Default` - где осмысленно. Enum вместо строковых состояний. Builder для сложных конструкторов.
- Никакого отладочного мусора: `dbg!`, отладочные `println!`/`eprintln!` не коммитить.

### Именование

- Типы и трейты - `PascalCase`; функции, методы, модули - `snake_case`; константы - `UPPER_SNAKE_CASE`.

## 🏛️ Архитектура

```
src/
├── main.rs          # CLI entry point
├── lib.rs           # Публичный API
├── config/          # Конфигурация
├── parser/          # Лексер и AST
├── formatter/       # Правила форматирования
└── io/              # Файловый ввод-вывод
```

- Модули изолированы: зависимость только через публичные интерфейсы (traits).
- `parser` не знает о `formatter` (общение через AST); `io` не знает о `parser`.
- Избегай циклических зависимостей, глобального состояния (`static mut`), избыточных `pub`.
- Dependency Inversion: завись от трейтов, а не конкретных типов.
- Boy Scout Rule: оставь модуль чище, чем нашёл - мелкую грязь рядом с задачей убери.

## 🧪 Тесты

- Пишутся вместе с кодом, не после. Один тест = один сценарий. Структура Arrange-Act-Assert. Моки через trait objects или `mockall`.
- Unit рядом с модулем: `#[cfg(test)] mod tests` в файле; крупные наборы - в соседний файл через `#[cfg(test)] #[path = "<имя>_tests.rs"] mod tests;`. Integration-тесты - в `tests/`.
- `proptest` на инварианты форматтера: идемпотентность (повторный прогон не меняет вывод) и round-trip (сохранение семантики AST).

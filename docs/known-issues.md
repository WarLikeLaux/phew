# Известные баги

## 1. Многострочное замыкание в частично-развёрнутом массиве — нестабильный отступ

**Статус:** не исправлено. Нужна переработка учёта глубины в `reindent_php_block`
(`src/formatter/indent.rs`) и функциях разбиения в `src/formatter/split.rs`.

### Как воспроизвести

```php
<?php $config = ["x" => function ($model) { return $model->status; }, "header" => ["aaaaaaaaaaaaaaaaaaaaaaa" => $model->attribute, "bbbbbbbbbbbbbbbbbbb" => $model->other, "cccc" => $model->more]]; ?>
```

Сохрани в файл и прогони форматтер дважды:

```sh
phew bug.php > p1.php
phew p1.php  > p2.php
diff p1.php p2.php   # ← есть разница, форматирование нестабильно
```

### Что не так

```
ПРОХОД 1                                  ПРОХОД 2
}, "header" => ["aaa…" => $model->attr,   }, "header" => ["aaa…" => $model->attr,
"bbb…" => $model->other,        ← 0 отст.     "bbb…" => $model->other,    ← 4 отст.
"cccc" => $model->more]]; ?>    ← 0 отст.     "cccc" => $model->more]]; ?> ← 4 отст.
```

Элементы вложенного массива `"header" => [ … ]` после закрывающей `}` замыкания
получают 0 отступа на первом проходе и 4 — на втором. Форматтер не идемпотентен.

### Корень

Строка `}, "header" => [ … ]` начинается с «висячей» `}` (закрывает `{` замыкания
с предыдущей строки). При разбиении этой длинной строки сплиттер считает скобки
с нуля и не знает, что мы уже внутри внешнего `[`.

Глубже: `emit_reindented_line` меняет глубину на `net.clamp(-1, 1)` — не больше
±1 за строку. Когда одна строка открывает сразу две скобки (`[` массива и `{`
замыкания), счётчик поднимается лишь на единицу и недосчитывает; при закрытии
`}` баланс уже сбит. Просто убрать `clamp` нельзя — он удерживает корректное
поведение десятка array/closure-фикстур (проверено: ломает 09, 18, 21, 91, 102).

### Область влияния

Только патология: длинный **однострочный** массив-присваивание с многострочным
`function () { … }` и вложенным массивом после него. Реалистичные формы
идемпотентны и форматируются корректно:

- короткое тело замыкания (остаётся инлайн);
- `GridView::widget([...])` и прочие вызовы (идут чистым путём `split_by_args`);
- массив, который разворачивается полностью по одному элементу на строку.

## 2. Битый HTML с несбалансированными тегами — схлопывание пробелов

**Статус:** не исправлено, низкий приоритет (только некорректный ввод).

Лишние закрывающие теги (`</div>` без открывающего и т.п.) выбрасываются, и
соседние пробельные текст-фрагменты дают лишний пробел, который схлопывается на
втором проходе. На корректной разметке не воспроизводится.
